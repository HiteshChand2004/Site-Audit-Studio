This website already exists. The project folder holds the owner's real source code; when <site_content> is given, it is what
the same site shows visitors today on its live address, read by this tool.
- Read before you change: study <source_code>, the relevant files (with the tools) and <site_content> first. Use the live site
  to see the current result (its pages, copy, facts and brand) and the code to see how it is built; the code is what you change.
- Treat it as their codebase: follow its existing structure, naming, formatting, component patterns and styling approach (CSS
  modules, Tailwind, plain CSS…) rather than introducing your own.
- Keep everything the brief does not change: page addresses, content, contact details and working links.
- Do not add dependencies unless a requirement cannot be met without one, and then say so in finish. Do not touch configuration,
  build or deployment files unless the brief asks for it.
