# Site Audit Studio — Website Audit & Recreate Platform

Internal tool: keeps all company websites in one place, audits them and recreates an improved version in a chosen stack. Company-owned or authorized sites only.

## Layout
Sidebar (mark, "All websites" home, "Add a website", search, each site's favicon + progress marks, Ctrl+B rail) + home gallery + one **dashboard per website** (see "UI revamp"). Inside a site, guided steps **1 Check → 2 Create the copy → 3 Compare → 4 Results & download** (see "UI redesign").
- **Check / OLD**: URL + Analyze → preview (sandboxed iframe, or the Analyze screenshot when framing is blocked; Live/Shot; 1440/768/375) → metrics → audit report (tech stack + confidence, weaknesses, SEO, AEO, meta/sitemap/robots, broken links, a11y, "manual rebuild needed").
- **Copy / NEW**: Recreate + stack settings → preview of the copy (own localhost port) → fix checklist (fixed / still open / manual) → Download .zip.

## Tech stack
- Client: React 19 + Vite 6, Zustand, lucide-react, CSS Modules + tokens (`client/src/styles/tokens.css`). Port **5173**, `/api` proxied to 4000.
- Server: Express 5 (ESM). Port **4000**. DB: SQLite via built-in **`node:sqlite`** (`DatabaseSync`, Windows-safe), Node ≥ 22.13, `--disable-warning=ExperimentalWarning`.
- Analyze: playwright (Chromium), lighthouse + chrome-launcher (forked worker), @axe-core/playwright, cheerio, robots-parser. Preview/security: sharp (WebP), undici (fetch with connect-time SSRF check).
- Recreate: esbuild (minifies `dist/` CSS/JS), html-validate (standard + document, offline), archiver (zip streamed).
- Build toolchains are NOT server dependencies: `server/toolchains/<id>/` (own package.json + node_modules, gitignored), `npm run setup:toolchains -w server -- <react-vite|next|mern>`: react-vite (vite 6.3.5, plugin-react 4.5.0, react 19.1.0), next (15.5.27, react 19.1.9), mern (react-vite's + express 5.2.1, compression 1.8.2, mongodb 7.7.0). Generated projects pin the same + `overrides: { rollup: 4.40.2 }` (Rollup 4.64 tree-shaking took 3–5 min).
- Planned: get-port, execa.

### Resume an interrupted Recreate — branch `resume-recreate` (worktree `../Website-Audit-resume`, from `fix-all` 7526d79), WIP
User: a Recreate that fails or is interrupted (error, time limit, restart, crash) must not lose its work. General.
- **Checkpoint** (`recreate/checkpoint.js`): atomic `checkpoint.json` in `<recreateId>.tmp`: `discovery` (once), `pages` (finished captures by discovery index), `sweep`, `steps` (inspect / sweep / assets: report keys, warnings / manual / errors, ctx fields), `stopped` { at, step, reason `error` | `time-limit`, message, progressed } (none = server died), `autoResumes`, `resumed[]`.
- **Failure**: workspace kept when pages were found; time-limit errors carry `timeLimit`. Success removes the checkpoint.
- **Resume** (`runRecreate({ resumeFrom: { recreateId, auto? } })`): `workspace.js adoptWorkspace` renames the `.tmp`; `clearUnfinished` removes site, dist, ir, fidelity, stacks, unfinished assets and capture folders; finished steps restored; `inspect.js` / `sweep.js` reuse saved work; generate → responsive run again with a fresh budget. `report.resumed[]` = { at, fromRecreateId, fromStep, stoppedStep, reason, pagesReused, stepsReused, auto } + warning "Continued after an interruption (N pages reused).".
- **Which one** (`findResumable`): newest failed recreate since the latest success with a usable checkpoint, < `RESUMABLE_DAYS` 7; `pruneRecreates` keeps that `.tmp`.
- **By itself** (`jobs.js autoResume`, ≤ `MAX_AUTO_RESUMES` 2 in a row, reset by a manual continue): after a server restart (`interruptedRecreates`, `resumeInterruptedRecreates`) and after a time-limit stop that made progress. Errors are left to the user.
- **API**: `POST …/recreate { resume: true }` (409 nothing to continue / running; 202 + `resumeFrom`); `GET …/recreate` → `resumable` = { recreateId, step, stoppedStep, pagesDone, pagesTotal, stoppedAt, reason (`error` | `time-limit` | `restart`), message } or null.

## Analyze (Phase 2) rules
- **Time limit** 6 min, 2 kept for Lighthouse; steps cut short or skipped (listed in `audit.errors`). One analysis at a time.
- **Sleep / outage retry** (`audit/interruptions.js`): a timeout / network error is explained first: (1) 1 s timer ≥ 5 s late = sleep (`watchPauses`); (2) HEAD to the site; (3) DNS query to the resolver (answer = network up, site hangs → reported). Sleep or outage → wait for the site (every 5 s, ≤ 2 min × `SAS_TIMEOUT_SCALE`; homepage ≤ 30 s) and run the step **once more** with its remaining time (≤ 5 min × scale total; shared by parallel steps). A plain timeout on a working network is never retried. `watchNetwork` DNS check every 3 s; a step overlapped by an outage is retried even if the network is back. Tests `interruptions`.
- **Keep-awake** (`jobs/keepAwake.js`): held by the global lock while a job runs / queues, released 30 s after: Windows hidden PowerShell `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)`, macOS `caffeinate -di -w <pid>`, Linux `systemd-inhibit`. Lid / power button still sleep. `SAS_KEEP_AWAKE=0` off; failure logged once. `GET /api/health` → `keepAwake`. Tests `keep-awake`.
- **Concurrency cap** `SAS_MAX_PARALLEL` (1–8) caps browser contexts everywhere; `1` also disables the background sweep beside generate/build (unless `SAS_RECREATE_OVERLAP=1`).
- **Slow machines**: `SAS_TIMEOUT_SCALE` (1–4) multiplies every limit and the total; `SAS_ANALYZE_MINUTES` (1–30) sets the total. One-page room → screenshots wait for the homepage render. Timeouts with < 1 GB free add a `memory` row. No `.env` required.
- **Links**: 4xx / 5xx, DNS, refused, bad TLS = broken; 401, 403, 429, 999, timeouts = unverified; ≤ 500 links.
- **Scope**: Lighthouse, axe, stack detection on the homepage; SEO, AEO, meta, links on all crawled pages (`max_pages` 25, depth 3).

## Preview & network security (Phase 3) rules
- **SSRF guard** (`server/src/security/`): user URLs reach public addresses only (loopback, private, CGNAT, ULA, link-local, reserved, IPv4-in-IPv6 blocked), checked on the resolved IP at connect time and every redirect hop. Node: undici Agent that resolves, checks and pins; Playwright + Lighthouse: per-job egress proxy (`egressProxy.js`).
- `SAS_ALLOW_LOCALHOST=1` (e.g. `server/.env`): loopback only, never port 4000. Internal allowlist only via `createNetPolicy({ internalPorts })` from code, never user input.
- **Frame check** (`audit/frame.js`): CSP `frame-ancestors` (must allow `APP_ORIGIN`, default `http://localhost:5173`) overrides X-Frame-Options; Report-Only and `<meta>` ignored; ALLOW-FROM / frame-busting = `confidence: 'uncertain'`.
- **Iframe**: `sandbox="allow-scripts allow-same-origin"`, `allow=""`, no referrer; never frames its own origin.
- **Screenshots**: 1440×900 (DPR 1), 768×1024 (DPR 1), 375×812 (DPR 2, mobile UA); fold + full (≤ 8000 CSS px), WebP q75 in `…/audit/<analysisId>/screens/`, whitelisted route, immutable caching; latest 3 analyses keep them.

## Conventions
- **All product text in English** (UI, API errors, dummy data, comments, docs), though the user chats in Hinglish.
- Theme: **calm light theme with warm orange accent** (`--accent` #c2410c, white text 5.2:1, amber tints, `--accent-rgb`). Colours, gradients, radii, shadows, motion are tokens in `tokens.css`; **colours only via tokens**. Keyframes in `styles/global.css`, used via variables (`animation: var(--k-fade-up) …`; `:global()` in `animation` breaks the build).
- Sidebar favicons (`routes/favicon.js`, `GET /api/projects/:id/favicon`: `<link rel=icon>` or /favicon.ico through the SSRF guard, ≤ 256 KB, SVG sanitized, sandbox CSP, cached as `favicon.bin` + `favicon.json`, retried after a day; `SiteIcon` falls back to the letter).
- Motion: staggered fade-up, hover lifts, score rings + count-up (`CountUp.jsx`), shimmering progress; off under reduced motion.
- Gotcha: a flex child with `overflow: hidden` is squashed in a flex column — give it `flex: none`.
- The audit JSON shape (`server/src/dummy/audit.js`) is the UI contract; `audit/assemble.js` produces it; new fields additive only (`test/analyzers.test.js`).

## Currently dummy / known issues
- Never-analysed projects get the **dummy** audit (`isDummy: true`, "Dummy data" badge) and a wireframe OLD preview; the checklist is a sample until a re-audit finishes.
- One preview per project; a newer recreate / stack build replaces only that project's preview.
- Recreate CSS: px per breakpoint unless fluid type was adopted; between captured widths layout relies on % / max-width / fr heuristics (exact mode keeps the site's own CSS instead).
- Lighthouse ~20–40 s per device; a healthy analysis a little over a minute; slow sites up to 6 min.
- Pre-Phase-3 audits lack screenshots / desktop metrics (UI asks to re-run).
- Some frameable sites render blank (frame-busting, cookie walls): use Shot. Cookie banners appear in screenshots. Full-page shots stop at 8000 CSS px.
- SSRF guard pins the first IPv4 (no IPv6 fallback); blocked requests listed in `audit.blockedHosts`.
- Bot-protected sites (Cloudflare challenge) fail with a clear message, never bypassed.
- Jobs live in memory; a restart marks running jobs failed (a Recreate can continue itself). The dev server doesn't use `node --watch` (Windows restarted it with nothing edited); `server/scripts/dev.js` watches only `src/` and `.env`, restarts only on a real content change and waits while `GET /api/health` reports `busy`. **Agents**: an edit to `server/src` restarts the user's dev server once idle — work in a git worktree while the user tests.
- 2 `netGuard` tests fail on this Windows machine (`*.localhost` → ENOTFOUND); not a regression.
- `POST …/export` returns the recorded output; deleting `stacks/` by hand isn't a rebuild (remove `outputs.<stack>` first).
- LF→CRLF warnings on Windows are harmless.
